## Как Заполнять Отчет

- В каждом разделе приведен план работы, а не утверждение о выполненной проверке.
- Под блоком **Место для скриншота** вставьте свое изображение. Пример Markdown указан в кодовом блоке: после добавления файла уберите окружающие тройные обратные кавычки, чтобы изображение отображалось.
- Имена файлов в примерах условные. Их можно заменить реальными именами ваших скриншотов, расположенных рядом с этим README.
- Для консольных заданий покажите команду запуска и вывод, для веб-приложений оставьте видимой адресную строку, для GUI-приложений покажите само окно.
- Не включайте в скриншоты пароли, токены и содержимое файлов с секретами.

## Перед Началом

Работайте в отдельной папке для каждого проекта. Команды выполняйте из каталога с его Dockerfile; для Linux-команд и графических приложений используйте WSL/Ubuntu или Linux. Для оконных приложений потребуется работающий WSLg или X-сервер.

Проверьте доступность Docker командами `docker version` и `docker ps`. Несколько заданий используют порт `8081`: перед следующим запуском остановите предыдущий контейнер, занимающий этот порт, либо выберите другой внешний порт.

`docker build` создает образ, `docker run` запускает контейнер. Флаг `--rm` удаляет контейнер после завершения, `-it` нужен для интерактивного терминала, а `-p` публикует порт. Инструкция `EXPOSE` сама по себе порт на хосте не открывает.

[Исходное задание](../../content/Docker/DockerFile/hello-world.md)

**Описание:** Публикация собственной HTML-страницы через Nginx в контейнере. Дополнительно изучается монтирование локального каталога: оно позволяет изменять страницу без пересборки образа.

5. Запустить в Bash: `docker run -d -p 8081:80 --name my-site -v "$(pwd)":/usr/share/nginx/html my-site`.
6. Открыть `http://localhost:8081`, изменить локальный HTML и обновить страницу для проверки монтирования.

**Место для скриншота:** Браузер с собственной страницей и адресом `localhost:8081`.

Для каждой связки подготовьте собственные Dockerfile на базе подходящих образов. PostgreSQL и веб-интерфейс запускайте в отдельных контейнерах в общей пользовательской Docker-сети. Для подключения из веб-интерфейса используйте имя контейнера БД, а не `localhost`. Пароли передавайте при запуске, не записывайте их в Dockerfile.
